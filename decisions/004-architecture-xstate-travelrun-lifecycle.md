# ADR-004 · architecture · XState управляет только жизненным циклом TravelRun

Используем XState v6 alpha как process manager для одной пользовательской
операции `TravelRun`. XState фиксирует состояния `idle`, `running`,
`waitingForUser`, `completed`, `failed` и `cancelled`, сериализует события из UI
и agent runtime, хранит snapshot и отдаёт стабильную проекцию виджету. XState не
решает, когда вызывать погоду, Tutu или web search. Эти решения принимает
TravelAgent.

## Что ещё рассматривали

- Хранить только `status` в SQLite. Этого хватит для простого запроса, но при
  SSE, отмене, уточнении пользователя и восстановлении состояние быстро
  разъезжается по handlers.
- Использовать XState как полный tool orchestrator. Это дублирует Agents SDK и
  заставляет писать смысловые эвристики в guards.
- Использовать `@statelyai/agent` в основном flow. Пока не нужно: агентный loop
  уже делает Agents SDK, а alpha-слой добавит риск.

## Последствия

- XState-типы должны быть изолированы в runtime-слое.
- Guards проверяют только технические инварианты: активен ли run, можно ли
  принять ответ, не завершён ли процесс.
- Для alpha-версии нужна точная фиксация версии и отдельный upgrade-процесс.
- Если после вертикального слайса машина сведётся к `running/completed/failed` без
  уточнений, отмены и восстановления, XState можно будет удалить.
