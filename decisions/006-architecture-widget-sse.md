# ADR-006 · architecture · Виджет получает продуктовые события через SSE

Живой виджет получает обновления через SSE, а команды пользователя отправляет
обычными HTTP POST-запросами. Такой транспорт подходит текущему продукту: сервер
стримит прогресс, карточки и итог, а пользовательские действия редкие и
командные. WebSocket пока не нужен.

## Что ещё рассматривали

- Оставить только один HTTP-ответ. Пользователь снова будет ждать вслепую.
- WebSocket. Даёт двусторонний канал, но усложняет reconnect, деплой и отладку.
  Для первого слайса достаточно SSE.
- Стримить raw events Agents SDK. Это привяжет UI к внутреннему протоколу агента.

## Последствия

- Backend публикует только продуктовые события: progress, widget state,
  waiting-for-user, completed, failed.
- Lit-виджет не знает о внутренних событиях модели, MCP и XState.
- При переподключении виджет сначала забирает текущий snapshot, затем слушает SSE.
