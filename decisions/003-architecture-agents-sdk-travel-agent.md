# ADR-003 · architecture · Один TravelAgent на Agents SDK

Для первого живого слайса используем OpenAI Agents SDK и один `TravelAgent` на
GPT-5.6. Агент получает пользовательский запрос, сам выбирает инструменты,
вызывает Tutu MCP, web search, weather tool и deterministic difference tool.
Так мы не строим ручной маршрутизатор из `if/else` и не переносим смысловые
решения в код. Код отвечает за инструменты, схемы, лимиты, ошибки и формат
результата.

## Что ещё рассматривали

- Codex-first через Codex SDK. Хорошо для workspace/coding-задач, но продуктовая
  задача шире: транспорт, погода, web search и объяснение пользовательской
  разницы.
- Codex как MCP worker внутри Agents SDK. Оставляем как возможный будущий worker,
  но не делаем обязательным для первого слайса.
- Multi-agent. Пока рано: у нас нет доказательства, что один агент не справится.

## Последствия

- Главный агентный цикл находится в Agents SDK.
- Инструкция агента должна быть короткой и проверяемой.
- TravelAgent возвращает структурированный `TravelAgentResult`.
- Evals важнее ручных эвристик: решение о втором агенте принимаем после реальных
  прогонов.
